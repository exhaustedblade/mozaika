# Мозаика — открытая среда имитационного моделирования (рабочее название)

**Статус:** идёт проба «Фаза 0» (с 21.10.2026). Есть каркас репозитория (Ф0-1), ядро времени (Ф0-2), первые блоки процессов (Ф0-3), агенты с диаграммами состояний (Ф0-4), ядро на данных в массивах (Ф0-4б), блоки на событиях, где сущность — агент (Ф0-4в), движение агентов со снимками для показа, ядро в Web Worker (Ф0-6а), и 3D-сцена на Babylon.js с демо «пункт обслуживания» и страницей замера (Ф0-6б). Основная работа — после версии 1.0 плагина Architect.

**Цель:** открытое приложение для имитационного моделирования, современнее нынешних (AnyLogic и др.) и не хуже по качеству. Процессы (дискретно-событийный подход), агенты и системная динамика живут на одних часах. ИИ строит и проверяет модели. Модель открывается по ссылке в браузере, в VS Code или в настольном приложении.

**Как не потратить 10 лет:** сами пишем только 4 вещи — единое ядро времени, библиотеку блоков, редактор и ИИ-слой с проверкой модели. Всё остальное (3D, карты, трафик, пешеходы, данные, графики, оптимизация) берём из открытых проектов.

## Разработка

Нужны Node.js 22.12 или новее (в CI — 24, см. `.nvmrc`) и pnpm: `npm install -g pnpm`, нужная версия из `package.json` подтянется сама.

| Команда | Что делает |
|---|---|
| `pnpm install` | ставит зависимости |
| `pnpm check` | все проверки, как в CI: типы, линтер, тесты, сборка, замер скорости |
| `pnpm typecheck`, `pnpm lint`, `pnpm test`, `pnpm build`, `pnpm bench` | те же проверки по отдельности |
| `pnpm dev` | viewer локально, с обновлением при правке |
| `pnpm --filter @mozaika/viewer e2e` | проверки показа в браузере (Playwright) на собранном превью: сначала `pnpm build`; браузер — `pnpm --filter @mozaika/viewer exec playwright install chromium` или свой через `PLAYWRIGHT_CHROMIUM=<путь>` |

Пакеты: `packages/kernel` — ядро времени, агенты с диаграммами состояний и движением, снимки популяций и хозяин ядра для Web Worker (`@mozaika/kernel/worker`), `packages/blocks` — блоки процессов (Source, Queue, Service, Delay, Sink, ResourcePool) на событиях ядра, `packages/viewer` — просмотр в браузере: главная с 2D-проверкой движения, демо «пункт обслуживания» (`demo.html`: 3D-сцена на Babylon.js, панель параметров, графики ECharts, самопроверка модели) и страница замера сцены (`bench.html`); ядро — в Web Worker, `packages/mcp` — MCP-сервер для ИИ. Пакеты подключают друг друга из исходников, поэтому тесты и проверка типов работают без предварительной сборки.

**CI** (`.github/workflows/ci.yml`) запускается на каждый пулл-реквест и push в main: Types, Lint, Tests, Benchmark, Build, Scene. Benchmark прогоняет около 1 млн событий через ядро (с малой и с большой очередью), гоняет модель M/M/1 на блоках, меряет 100 000 и 1 000 000 агентов — неподвижных и движущихся (вместе с временем позиций и снимка популяции) — и 100 000 сущностей одновременно в Delay (единиц модельного времени в секунду и память) и пишет таблицы в сводку job'а (Summary); рядом — цифры до Ф0-4б, Ф0-4в и Ф0-6а, замеренные в CI. Scene прогоняет страницы собранного превью в Chromium (Playwright): демо и страница замера рисуются и кадр не пустой, модель держит свои законы, шейдер на видеокарте совпадает со своим двойником на TypeScript; замер 100 000 идущих агентов и размер скриптов — в сводке job'а, скриншоты — артефактом `scene-screenshots`. Видеокарта в CI программная, поэтому кадры там — ориентир, а цель — 30 кадров в секунду на 100 000 — проверяется на компьютерах владельца (инструкция — на странице замера). Когда всё зелёное, шаг Preview публикует viewer в ветку `gh-pages`: main — в корень сайта, пулл-реквест — в папку `pr-<номер>/`. Ссылка приходит комментарием в пулл-реквест, после его закрытия папка удаляется.

**GitHub Pages включается один раз** (делает владелец): Settings → Pages → Build and deployment → Source: «Deploy from a branch», ветка `gh-pages`, папка `/ (root)`. Ветка появляется после первого зелёного CI. Для приватного репозитория Pages доступен только на платном тарифе GitHub.
