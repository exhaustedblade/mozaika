| Р-1 | Стек | веб/TypeScript (ядро, редактор, сцена) · Godot + C# | **веб/TypeScript**: один язык, ссылка в браузере, работает в VS Code, ИИ лучше всего пишет TS; Godot позже как «кинорежим» | владелец, после Фазы 0 |
| Р-2 | Когда начинать | сейчас · после Architect 1.0 · проба сейчас, проект после | **проба сейчас по желанию, проект после 1.0** (правило владельца: до 1.0 не отвлекаться) | владелец |
| Р-3 | Лицензия проекта | Apache-2.0 · MIT · AGPL | **Apache-2.0**: разрешительная, с патентной защитой, совместима с open core | владелец + юрист |
| Р-4 | Название | «Мозаика» (рабочее) · другое | проверить свободность имени и домена | владелец |

| Р-6 | Импорт моделей других программ | XMILE (открытый стандарт) · Vensim · AnyLogic .alp | XMILE и Vensim — да; .alp — только после консультации юриста | владелец + юрист |
| Р-7 | Порядок: «сначала ИИ, потом визуальный редактор» | модели — код, который пишет ИИ; просмотр сцены, графиков, панелей и блок-схемы (только чтение); правка словами · сразу полный визуальный редактор | **«сначала ИИ»**: прототип за 1–2 недели, пересборка демо за 4–6 недель; редактор с перетаскиванием — потом, по запросу пользователей | владелец |
| Р-8 | Оболочка настольного приложения (П-19) | **Electron**: везде один и тот же Chromium, поэтому графика и WebGPU ведут себя предсказуемо; установщик порядка 100 МБ и больше (архив самого Electron 45 — 121–158 МБ, проверено 21.10.2026) · **Tauri**: маленький установщик, но движок системный — на Windows WebView2 (Chromium), на macOS WebKit. Значит, проверять на двух движках; WebGPU в WebKit включён по умолчанию только с macOS 26 Tahoe (так ли это внутри приложения Tauri — проверить в Ф0-6) | решить по замеру в Ф0-6: одна и та же сцена в обеих оболочках, кадры в секунду и память на Windows и macOS | владелец |

## Принятые

| № | Решение | Когда | Почему |
|---|---|---|---|
| П-1 | Сами пишем только ядро, блоки, редактор и ИИ-слой с проверкой; остальное берём открытым | 21.10.2026 | иначе 10 лет |
| П-2 | Никакого кода, иконок и интерфейса AnyLogic; только «чистая комната» | 21.10.2026 | лицензия AnyLogic запрещает декомпиляцию; юридическая чистота |
| П-3 | Ядро без отрисовки, показ отдельно | 21.10.2026 | быстрые эксперименты, проверяемость, разные оболочки |
| П-4 | Маршруты только через онлайн-сервисы | 21.10.2026 | так же решено для Architect (08.10): офлайн-маршрутизация не нужна |
| П-5 | Каркас пробы (Ф0-1): monorepo на pnpm workspaces (`kernel`, `blocks`, `viewer`, `mcp`), TypeScript strict, Vitest, ESLint, Vite для viewer, CI в GitHub Actions на Node 24. Превью — ветка `gh-pages`: main в корне сайта, каждый пулл-реквест в папке `pr-<номер>/` | 21.10.2026 | инструменты задал владелец в задаче Ф0-1; Vite — стандартная сборка для веба; своя папка на пулл-реквест — чтобы у каждого была своя ссылка (официальный деплой Pages держит только одну версию сайта). Стек остаётся пробным до решения Р-1 |
| П-6 | Репозиторий открыт уже в Фазе 0, а не при версии 0.1 | 21.10.2026 | GitHub Pages для приватного репозитория требует платного тарифа, а превью по ссылке нужно с первой задачи. Пока нет файла LICENSE (Р-3 открыто), код виден всем, но права на него не переданы никому |
| П-7 | Модельное время — число (double) в единицах модели. Одновременность — точное равенство времён, без допуска. Моменты снимков считаются как `start + k·every`, без накопления | 21.10.2026 | Допуск при сравнении ломает транзитивность сравнения в куче, и порядок событий перестаёт быть детерминированным. Целые «тики» неудобны для системной динамики и пересечения порогов (Ф0-5), где время дробное. Так же сделано в SimPy |
| П-8 | Правило одновременных событий: время, затем приоритет (меньше — раньше, по умолчанию 0), затем порядок постановки в очередь. Старт процесса и пробуждение по сигналу — новые события в текущий момент. Снимок в момент T — после всех событий с временем ≤ T; `run(until)` включает события ровно в момент `until` | 21.10.2026 | Порядок полный и не зависит от устройства кучи. «Первым поставлен — первым сработал» — ожидаемое поведение (учебники, SimPy). Состояние «после событий момента T» — обычное соглашение теории случайных процессов: приход в момент T в этот момент уже учтён |
| П-9 | Случайные числа: свой генератор xoshiro128\*\* (Blackman, Vigna, 2018). Состояние потока выводится из seed и пути имён через SplitMix64. Поток — на каждый источник случайности и на каждый повтор эксперимента. У экспоненциального распределения параметр — среднее | 21.10.2026 | Около 100 строк без зависимостей; только 32-битные операции, поэтому быстро в JS; по данным авторов, проходит известные статистические тесты. Потоки по именам не зависят от порядка создания и от расхода чисел другими потоками, поэтому сценарии сравниваются на общих случайных числах. Среднее задаётся в единицах времени, как задержка. Ограничение: побитовая повторяемость гарантирована в одном движке JS — `Math.log1p` может отличаться в последнем бите |
| П-10 | Замер скорости ядра — скрипт `packages/kernel/bench/events.ts`: `pnpm bench` (входит в `pnpm check`) и job Benchmark в CI с таблицей в сводке job'а. Порог — 250 000 событий в секунду, примерно в 10 раз ниже фактической скорости | 21.10.2026 | Без новых зависимостей: Node сам выполняет TypeScript, типы `console` и `performance` берутся из библиотеки DOM, `@types/node` не нужен. Низкий порог ловит настоящие регрессии (например, очередь, ставшую линейной), но не падает на медленной машине CI |
| П-11 | Код пишем чисто и понятно, на уровне сеньора: понятные имена, небольшие функции с одной задачей, комментарии объясняют «почему». Правило записано в `CLAUDE.md` | 21.10.2026 | Правило владельца: код должен легко читаться человеком |
| П-12 | Историю git не переписываем, force push не делаем. Тексты, удалённые из файлов 21.10.2026, остаются в старых коммитах | 21.10.2026 | Решение владельца. Переписывание истории публичного репозитория ломает чужие копии (клоны и форки) и не убирает то, что уже скопировано |
| П-13 | Блоки процессов (Ф0-3, `docs/BLOCKS.md`): сущность — процесс ядра, который проходит блоки по порядку; у блока один выход (`connect`), вход — интерфейс `EntityReceiver`. Имя блока обязательно и уникально в симуляции; случайные числа блока — из потока `blocks/<имя>`. В ядро добавлен только код ошибки `INVALID_STATE` | 21.10.2026 | Подход «взаимодействия процессов» из учебников и SimPy: логика блока читается сверху вниз, ожидание ресурса или места — обычный `yield`. Поток по имени блока не сдвигается от правки других блоков (П-9), а уникальность имени не даёт двум блокам случайно делить поток. Остальное блокам дал публичный API ядра |
| П-14 | Движение и переполнение: сущность уходит из блока, только когда в следующем есть место; до тех пор ждёт в своём, занимая место (блокировка). Места выдаются в порядке ожидания. Вместимость у Queue, Service и Delay необязательна (по умолчанию без ограничения); у Service она общая для ждущих и обслуживаемых. Source не держит сущности: приход без места теряется и считается в `source.lost`. Service держит единицу ресурса, пока следующий блок не примет сущность | 21.10.2026 | Блокировка — общее правило цепочек с ограниченными буферами (Gross & Harris); с ним у отдельной Queue есть смысл — держать сущности, пока дальше нет места. Потеря прихода у источника — классическая система M/M/c/K, её формулы проверяются тестами. Вместимость Service на весь блок — это K из обозначения M/M/c/K, а при K = c очередь образуется в отдельной Queue перед ним. Удержание единицы при блокировке — обычное поведение линий с буферами. Отказ с уходом по другому пути — позже, отдельной возможностью |
| П-15 | ResourcePool — строгий FIFO без перехвата: освободившаяся единица сразу передаётся первому ждущему и свободной не становится; ждущий продолжает событием в тот же момент. Пока выданный запрос не продолжил, новый запрос при свободной единице тоже продолжает событием, после него. Места в блоках выдаются так же | 21.10.2026 | Дисциплина FIFO из учебников; так же выдаёт запросы SimPy. Если вернуть единицу в свободные, процесс, пришедший в тот же момент, может её перехватить, а при детерминированных временах одновременные события — обычное дело. Второе правило не даёт новому запросу обогнать ждавший внутри одного момента |
| П-16 | Сверка блоков с теорией очередей — метод повторов с отбрасыванием разгона (Law, гл. 9): 20 повторов со своими потоками `new Random(seed, ['replication', String(k)])`; разгон — не меньше 13 времён релаксации; t-интервал уровня 99,9 %; полуширина — не больше 10 % значения. Закон Литтла проверяется точно на одной траектории и по средним повторов с допуском 0,5 % | 21.10.2026 | Повторы независимы по построению, а батчи одного прогона при ρ = 0,9 коррелированы, и их размер пришлось бы подбирать. Интервалов в наборе 26: при уровне 95 % хотя бы один промахивался бы почти всегда (≈74 %), и тесты держались бы на «удачном» seed; при 99,9 % ложное падение — не больше 2,6 % (неравенство Бонферрони). Предел полуширины не даёт ошибке спрятаться в широком интервале. Набор проверен на 40 seed: из 1 040 интервалов ни одного промаха, полуширина не выше 7,2 % |
| П-17 | Замер скорости блоков: в `pnpm bench` и job Benchmark добавлен сценарий M/M/1 на блоках (ρ = 0,9, около 1 млн событий) отдельной таблицей после таблицы ядра. Порог — 150 000 событий в секунду, примерно в 12 раз ниже фактической скорости | 21.10.2026 | Тот же подход, что в П-10: низкий порог ловит настоящие регрессии, но не падает на медленной машине CI. Блоки добавляют к событию ядра свою работу (генераторы, статистика, пул), поэтому порог ниже, чем у ядра |
| П-18 | Цель масштаба и графики: реалистичные цифровые двойники для масштабных проектов, без жёсткого потолка по числу агентов. Сотни тысяч агентов на десктопе — норма, миллион с простой логикой — цель. Графика — сильная сторона продукта: WebGPU, физически корректные материалы, тени, освещение, 3D-карты | 21.10.2026 | Решение владельца. Отсюда требования к архитектуре: ядро на десктопе — отдельным процессом, снимки больших популяций — плотными числовыми массивами (`docs/ARCHITECTURE.md`, «Большие популяции»), замеры на 100 000 агентов в Ф0-4 и Ф0-6 |
| П-19 | Главная форма продукта — настольное приложение для Windows и macOS. Браузер по ссылке остаётся для показа моделей заказчику | 21.10.2026 | Решение владельца. На десктопе больше памяти, чем у вкладки браузера, а эксперименты можно гонять параллельно на всех ядрах процессора. Оболочка (Electron или Tauri) — открытый вопрос Р-8. Подпись приложений нужна, когда появятся внешние пользователи (`docs/PLAN.md`, раздел 5) |
