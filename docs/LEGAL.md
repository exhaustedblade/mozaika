# Юридическая чистота: правила «чистой комнаты»

Это рабочие правила, не юридическая консультация. Перед коммерческим запуском нужна консультация юриста.

## Нельзя

- Декомпилировать jar-файлы и библиотеки AnyLogic (и любых закрытых программ), читать их код в любом виде, в том числе «просто посмотреть». Лицензия это запрещает, а код, написанный после чтения чужого, может быть объявлен производным.
- Брать их классы, структуру, внутренние имена, иконки, интерфейс, тексты справки один в один.
- Использовать утёкшие исходники.
- Называть продукт «совместимым с AnyLogic» или использовать их товарные знаки.

## Можно

- Читать открытую справку, описание API (Javadoc), учебники, статьи, примеры моделей из открытых источников.
- Изучать работу программы, запуская её, чтобы понять идеи и принципы. В России это ст. 1280 ГК РФ, в ЕС — директива о правовой охране программ.
- Реализовывать общепринятые понятия моделирования (очередь, задержка, ресурс, диаграмма состояний, запас и поток): это идеи из учебников, а не чья-то собственность.

## Порядок работы

1. **Спецификация поведения блока** пишется по справке, учебникам и наблюдениям: параметры, что происходит при переполнении, приоритеты, порядок событий.
2. **Реализация** — по спецификации, без доступа к чужому коду.
3. **Тесты** — против точных формул (теория очередей) и опубликованных эталонных моделей.
4. Если сверяем поведение с прогонами в AnyLogic, сначала проверяем, что условия лицензии это допускают.
